# Two AI paths, one task shape

Ligand can call a model itself (the built-in path) and can hand work to an external coding agent (the external path), so it works with or without a coding agent installed. Both paths take the same task (the node's contract, its tests, the current implementation and, for a fix, the captured failing case) and return the same result: an implementation diff that passes `ligand check`, or an escalation. One shape keeps the two paths from drifting apart in their rules and results.

## Consequences

- The built-in path is a thin loop over `effect/ai` (see ADR 0010), which is provider-agnostic, with the developer's own key: generate, run `ligand check`, feed back the failures, escalate after a fixed number of attempts. It is not a general coding agent. Next.js built an in-browser agent and later dropped it in favour of working with external agents.
- For a parked run that isn't a logic bug, such as a site that stayed down until retries ran out, the AI writes a diagnosis: a short report attached to the parked run, with no diff.
- Improve runs when `ligand check` fails the mutation gate, and produces example proposals. Suggesting refactors and splits is future work.
- In v1 the built-in path supports Anthropic, OpenAI and OpenRouter, the providers with Effect 4 packages; Gemini and Bedrock are reachable through OpenRouter.
- The external path's MCP server is `effect/ai`'s `McpServer.layerStdio`, sharing one tool definition with the built-in path, once it has been tested with Claude Code and Codex.
- The external path passes the task to a configured agent command and ships skills plus an MCP server for interactive use.
- `ligand init` writes steering, MCP configuration and skills for the agents you choose (Claude Code, Codex, GitHub Copilot, Cursor, Kiro, Gemini CLI), all generated from one source and regenerated by `ligand agents sync`:
  - Steering: Ligand's rules go into a marked section of `AGENTS.md`, which all six read (Gemini CLI through `context.fileName`). No `CLAUDE.md` is created, because Claude Code reads `AGENTS.md` itself when there is none; an existing `CLAUDE.md` gets an `@AGENTS.md` import.
  - MCP: `ligand mcp` is registered in each agent's project file (`.mcp.json`, `.codex/config.toml`, `.cursor/mcp.json`, `.kiro/settings/mcp.json`, `.gemini/settings.json`). Copilot's cloud agent has no repository file, so `ligand init` prints the JSON to paste into the repository settings.
  - Skills: `.agents/skills`, `.claude/skills` and `.kiro/skills`.
